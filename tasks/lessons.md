# lessons

- when rebuilding from an extracted site, do not default to visual approximation as the only path. first separate the goal into raw static clone, deterministic dom/css capture, and clean source rebuild, then explain which parts can be copied exactly from the deployed url and which parts require inference.
- when mirroring a framer template, do not stop at the first loaded page. crawl same-origin routes from anchors, capture each route's original navigation html, and verify project/detail pages over local http.
- for larger framer templates, parallelize route captures and discovered asset downloads with bounded concurrency instead of crawling everything serially.
- framer runtime can reconstruct remote cms/image urls after hydration. for high-fidelity mirrors, inject an early url map/import map shim and verify with external framer/font hosts blocked.
- when the user says to use a specific framer template, "copy the template" means preserve the mirrored framer runtime/dom/layout as the implementation base. do not replace it with a vibe-matched react rebuild unless the user explicitly asks for an editable clean port.
- when the user provides chat/downloaded images, search local temp/cache/download paths and verify dimensions before claiming the attachment needs a manual path. copy assets into stable project paths first, then wire them through config.
- broad brand text replacements can corrupt structured hero slots in framer exports. scope hero first/last-name fixes by `data-framer-name` instead of replacing every shared token globally.
- do not treat every impressive repo in the local github folder as portfolio-owned work. before adding a project publicly, confirm the user actually made it or that attribution/ownership is appropriate.
- when routing bugs show up in a hydrated framer mirror, debug the code path first: project config, rewrite normalization, generated deploy routing, and runtime link interception. use browser/manual checks only after the source behavior is understood.
- a framer page can load the rewritten route first, then hydrate and navigate again to the original cms/source slug. deploy routing must include source-slug redirects, not just redirects for the final public project slugs.
- for framer mirror work-card clicks, stop same-click framer routing at document capture time with `stopImmediatePropagation()`. stopping only bubbling can still allow framer to queue a second cms/source-slug navigation.
- do not describe old framer template slugs like `stone-mind` or `violet-orbit` as working projects. they are legacy redirect aliases only, and local dev should issue real redirects for them so they do not look like portfolio routes.
- for framer cms routing, patch the collection utils that hydrate route slugs before adding runtime click guards. `getSlugByRecordId()` and `getRecordIdBySlug()` are the root source of project link targets.
- when the Write tool errors with "File has not been read yet", the file is unchanged — after reading it, you MUST re-issue the Write or use Edit. silent assumption that a previous attempt landed will leave files at the create-next-app defaults (e.g., layout.tsx kept Geist + globals.css kept the demo theme even though build passed cleanly, because the unfilled theme/font swap was never required for compilation).
- next 16 ships turbopack as the default. mdx remark/rehype plugins must be passed as string names (`"remark-gfm"`) not imported function references — turbopack runs the mdx pipeline in rust and can't accept js function values.
- next 16 dynamic route params are a Promise: `params: Promise<{ slug: string }>` — must `await params` inside the page or generateMetadata.
- a captured framer mirror is a structural reference, not source. for a clean port, extract motion specs + design tokens + page-structure outline first, then rebuild in jsx — do not html-to-jsx the compiled output.
- gsap ScrollTrigger does not always fire its play action for elements already in view at hydration when paired with `gsap.set(node, hiddenState)` — content can stay hidden if ScrollTrigger doesn't refresh after layout settles (image loads, font swaps). for SSR + mount-once reveal use IntersectionObserver instead; only reach for ScrollTrigger when you need scroll-linked progress (parallax, scrub). save yourself a debugging session.
- playwright fullPage screenshots do NOT trigger real scroll events — ScrollTrigger animations may stay in their pre-state. either programmatically scroll the page in the script before the final shot, or use IntersectionObserver-based reveals which fire from layout alone.
- before replacing a distinctive interaction that is already deployed, compare localhost against production and preserve the deployed behavior as the regression baseline. for this portfolio, the home work section is the 13-card layered gsap loop with drag plus previous/next controls; a generic snap carousel is not an equivalent substitute.
- iphone heic files can exceed sharp/libheif's default reference-count security limit even when the image itself is valid. for portfolio assets, use macos `sips` to decode and resize the heic to an intermediate jpeg, then `cwebp` to create the optimized webp.
- when the user says to "just update vercel deployment," treat that as a direct production deploy from the already-linked app directory. do not route it through the full branch, version, changelog, and pr ship workflow unless they explicitly ask for release ceremony.
- preserve the loader's captured pacing unless the user explicitly asks to speed it up. shortening the counter and exit delays changes the whole first-impression rhythm even when the visual states remain identical.
- when the user names a specific prior deployment as the visual baseline, inspect that exact immutable deployment and compare frames directly. current comments, reconstructed specs, and neighboring deployments are not substitutes for the requested artifact.
- pin the homepage carousel's opening project by slug rather than by its midpoint. adding case studies changes the midpoint; verify the intended opening card as well as navigation and wrapping after inventory changes.
